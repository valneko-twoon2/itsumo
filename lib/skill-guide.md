itsumo のスキル。依頼が次のどれかに当たるときは、作業を始める前に Skill ツールで呼び、本文の手順に従うこと。

- 曖昧な依頼（「いい感じに」「適当に」「よしなに」）: itsumo:clarifying-requests
- 複数ファイルにまたがる大きな作業（機能の追加、移行、作り直し）: itsumo:planning-large-changes
- 既存のコードを直す・変える: itsumo:making-minimal-changes
- 新しいコードやテストを書く: itsumo:following-existing-code
- リファクタ、整理、共通化、分割: itsumo:refactoring-safely
- 不具合の原因を調べる、動かない・落ちる: itsumo:investigating-bugs
- テストの扱い、動作確認、「完了しました」と報告する前: itsumo:running-regression-tests
- テストケースの選び方、境界値: itsumo:designing-test-cases
- API・エンドポイントを足す、アップロードやユーザーが渡すファイル名・パス・URL を扱う、プロセスの起動、ログイン（「確認すべき点は」「セキュリティは」とも）: itsumo:reviewing-security-boundaries
- 削除、強制 push、reset、DB の書き換え、本番への操作: itsumo:handling-destructive-operations
- コミットする: itsumo:committing-changes
- PR を作る、PR の説明を書く: itsumo:writing-pr-descriptions
- 依存パッケージの追加・更新・アップグレード: itsumo:updating-dependencies
- 遅い・重い、速くしたい: itsumo:improving-performance
- マージやリベースのコンフリクト（衝突）: itsumo:resolving-merge-conflicts
- 並行作業のためのワークツリー: itsumo:managing-worktrees
- サブエージェントの成果を取り込む: itsumo:merging-subagent-work
- 初回のセットアップ（ユーザーが手動で実行するもの。自分からは呼ばない）: itsumo:setting-up-project

プロジェクトの決まり（AGENTS.md、CLAUDE.md）がスキルと食い違うときは、プロジェクトの決まりが正。
