# プロジェクトの調べ方

読むだけで調べる。広く浅く全体を見てから、気になる所を深く読む。

## 目次

1. 全体
2. 言語と道具
3. コマンド
4. 構造と規約
5. 繰り返す手順
6. 履歴と運用

## 1. 全体

- ルートのファイルとフォルダの一覧。`README.md`、`docs/`、`CONTRIBUTING.md` を読む。
- Git のリポジトリか。`git log --oneline -30` で、最近の変更の様子とコミットメッセージの流儀を見る。
- 規模: ファイル数、主な言語（拡張子の分布）。

## 2. 言語と道具

| 見るもの | 分かること |
|---|---|
| `package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod`、`pom.xml`、`*.csproj`、`Gemfile` | 言語、依存、パッケージマネージャ、スクリプト |
| `tsconfig.json`、`.eslintrc*`、`eslint.config.*`、`.prettierrc*`、`ruff.toml`、`.editorconfig`、`rustfmt.toml` | 型、リント、整形の決まり |
| `.github/workflows/`、`.gitlab-ci.yml`、`Makefile`、`justfile`、`Taskfile.yml` | ビルド・テスト・リリースの正式な手順 |
| `Dockerfile`、`docker-compose.yml`、`.env.example` | 実行環境、必要な環境変数 |
| `.gitattributes`、`.gitignore` | 改行、生成物 |

## 3. コマンド

次のコマンドを特定する。**ファイルから読み取り、実際に走らせて確かめる**（時間がかかるもの、外部に触れるものは走らせず「未確認」とする）。

- 依存の導入、ビルド、テスト（全体と 1 ファイル）、型チェック、リント、整形、起動。

## 4. 構造と規約

- 主要なフォルダの役割。エントリーポイント。層の分け方。
- 同じ種類のファイルを 3 つほど読み、**共通する書き方**を拾う（命名、エラー処理、ログ、テストの置き場所と書き方）。
- 設定を読む場所、データベースやスキーマの場所。

## 5. 繰り返す手順

次のような、手順が決まっている作業を探す。スキルの候補になる。

- 新しい機能の単位（API、画面、コマンド、モデル）を足すとき、毎回触る複数のファイル。`git log --stat` で、同じ組み合わせのファイルが一緒に変わっているものを探す。
- マイグレーション、リリース、コードの生成、スナップショットの更新。
- 文書や README の更新が要る変更。

## 6. 履歴と運用

- `git log` から、ブランチ名とコミットの流儀、PR の運用。
- `TODO`、`FIXME`、`HACK` の多い場所。壊れやすい場所は注意書きの候補になる。
- 既に決まりが書かれた場所（README の「開発」の節など）。AGENTS.md と二重にしない。
