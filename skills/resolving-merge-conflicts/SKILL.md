衝突は、**同じ場所を両側が変えた**というだけの印。どちらかを選ぶ前に、両側が何をしたかったかを読む。黙って片方を捨てると、機能や修正が静かに消える。

## 1. 状況を確かめる

進捗のチェックリスト:

```
- [ ] 何をしている最中か分かった（merge / rebase / cherry-pick）
- [ ] 衝突したファイルの一覧を見た
- [ ] 両側の意図を、ファイルごとに読んだ
- [ ] 解いた。衝突マーカーが残っていない
- [ ] 解いた結果でビルド・テストを通した
- [ ] 操作を完了した（continue / commit）
```

- `git status` で、最中の操作と、衝突したファイル（`both modified` など）を見る。
- **自分側と相手側の呼び名に注意する。** マージでは `ours` が今のブランチ、`theirs` が取り込むほう。リベースでは逆になる（`ours` が土台、`theirs` が今、自分のコミット）。
- 状況がおかしくなったら、`git merge --abort` や `git rebase --abort` で操作の前に戻れる。ただし、操作の前から未コミットの変更があるとき、それを失うことがあるので、先に状態を確かめる。

## 2. ファイルごとに解く

1. 両側の変更を読む。`git diff`（衝突の場所だけが出る）、`git log --merge -p -- <ファイル>`（両側の該当コミット）、`git show :1:<ファイル>`（共通の元）、`:2:`（ours）、`:3:`（theirs）。
2. 両側の意図を、1 文ずつ言えるようにする（例: 「こちらは税率を引数にした、相手は端数の丸めを変えた」）。
3. 決める。

| 状況 | 解き方 |
|---|---|
| 片方が明らかに置き換えた（改名、削除、書き直し） | 新しいほうを残し、古いほうの変更が新しいほうに入っているか確かめる |
| 両立する（別々の変更が同じ場所に隣り合った） | **両方を残す**。組み合わせた結果が文法的にも意味的にも正しいか読む |
| 同じ目的の変更が二重になっている | 1 つにまとめる |
| 意図が分からない、どちらも捨てられない | 手を止めて、ユーザーに両側の要約を示して聞く |

- ファイルごと `git checkout --ours` / `--theirs` で選ぶのは、中身を読んで、片方を丸ごと捨ててよいと確かめたときだけ。
- 生成されるファイル（ロックファイル、スナップショット、コードの生成物）は、手で解かず、**元になるファイルを解いた後にコマンドで作り直す**。
- よくある形:
  - 両側が末尾にキーを足した JSON（ロケールファイルなど）: 両方残し、古い最終行にカンマを足す。解いた後に `JSON.parse` などで読めることを確かめる。
  - 一覧や表の文書: 両方の行を残す。
  - import の並び: 両方の import を残し、重複を消す。
- 衝突を直すスクリプトは改行を保つ（または編集ツールを使う）。`git diff --stat` で、全行が変わったファイルが無いことを確かめる。

## 3. 解いた後に

- 衝突マーカー（`<<<<<<<`、`=======`、`>>>>>>>`）が残っていないことを、検索と `git diff --check` で確かめる。
- ビルド、型チェック、テストを走らせる（`/itsumo:running-regression-tests`）。**両側が触った領域のテストは全部**走らせ、その理由を報告に書く。マージの結果が、片方だけで通っていたテストを壊すことがある。
- 解いたファイルだけを名前を指定してステージし（`git add -A` を使わない）、操作を完了する（`git merge --continue`、`git rebase --continue`、または `git commit`）。
- リベースは、コミットごとに衝突が出うる。1 つ終えるたびに、2〜3 章を繰り返す。
- リベースの後の push に `--force` が要るときは、勝手にせず `/itsumo:handling-destructive-operations` に従う。

## 4. 報告

衝突したファイルごとに、どう解いたか（どちらを残したか、両方か）と理由。迷ったもの。走らせたチェックとその結果。

入力: 「main をマージしたらコンフリクトした」

出力:

```
衝突: src/price.ts、locales/ja.json の 2 ファイル。
src/price.ts: こちらは calcTax の引数を増やし、main は端数を四捨五入に変えていた。両立するので、引数を残したまま四捨五入にした。
locales/ja.json: 両側が末尾にキーを足していた。両方残し、カンマを直した（JSON として読めることを確認）。
確認: npm test（price と locale に関わる 23 件を含む全 84 件）が成功。
```
