# Web アプリ、Web API、サーバーの確認表

共通の確認（SKILL.md の 3 章）に加えて、変える境界に当たる行を確かめる。

| 境界 | 確かめること |
|---|---|
| 認証 | パスワードは bcrypt、scrypt、Argon2 のような遅いハッシュで保存する（平文、MD5、SHA-1、ソルト無しの SHA を使わない）。比較は定数時間で行う。ログインの失敗メッセージで、ユーザーの有無を漏らさない |
| 認可 | 認証の確認だけで済ませず、**そのリソースがそのユーザーのものか**をサーバー側で毎回確かめる（IDOR）。管理者向けの経路もサーバー側で権限を確かめる。UI で隠すのは防御にならない |
| セッション、トークン | Cookie には `HttpOnly`、`Secure`、`SameSite` を付ける。ログイン時にセッション ID を作り直す。トークンには有効期限を持たせ、ログアウトで失効させる。JWT は署名のアルゴリズムを固定し、`none` を受けない |
| CSRF | 状態を変える要求（POST、PUT、PATCH、DELETE）は、CSRF トークンか `SameSite` Cookie、独自ヘッダの確認で守る。GET で状態を変えない |
| CORS | `Access-Control-Allow-Origin` に `*` と認証情報（`Allow-Credentials`）を組み合わせない。許可するオリジンは完全一致の許可リストにし、受けたオリジンをそのまま返さない |
| XSS | 出力はフレームワークの自動エスケープに任せる。HTML 文字列を作って入れる（`innerHTML`、`dangerouslySetInnerHTML`、`v-html`、テンプレートの raw 出力）のは、信頼できる固定文字列だけ。ユーザーの入力が入る URL（`href`、`src`）は `javascript:` を拒む |
| セキュリティヘッダ | CSP を緩めない（`'unsafe-inline'`、`'unsafe-eval'`、`*`）。`X-Content-Type-Options: nosniff`、`Strict-Transport-Security`、クリックジャッキング対策（`frame-ancestors`）を外さない |
| アップロード | サイズ上限を入口で効かせる。拡張子と中身（先頭のバイト列）の両方を確かめる。保存名はサーバーが決め、元の名前を使わない。Web から直接配信できるフォルダに置かない。実行を許さない |
| 一括代入 | リクエストの本文をモデルにそのまま渡さない（`role`、`isAdmin`、`price` を書き換えられる）。受け取る項目を許可リストで決める |
| レート制限 | ログイン、パスワード再設定、コード送信、高価な処理には回数の上限を付ける。ユーザー単位と IP 単位の両方を考える |
| エラー、ログ | スタックトレースや内部のパス、SQL をクライアントに返さない。ログにパスワード、トークン、個人情報を入れない |
| リダイレクト、サーバー側の取得 | 遷移先や取得先 URL をユーザーが決められるなら、許可リストの完全一致にする。内部アドレス（`127.0.0.1`、`169.254.169.254`、プライベート範囲）を拒む（SSRF） |
| 設定、秘密 | 秘密は環境変数かシークレット管理から読み、コードやリポジトリに入れない。本番でデバッグ表示や既定の資格情報を有効にしない |
