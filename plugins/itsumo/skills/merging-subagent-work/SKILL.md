サブエージェントの報告は、本人がやったと思っていることにすぎない。このスキルはその報告と既定ブランチ（以下 main）の間の関門で、報告だけを根拠にマージはしない。守るべき決まりはプロジェクトの `CLAUDE.md` / `AGENTS.md` / `.claude/rules/` などにあり、ここは手順の順番だけを決める。

次のチェックリストを写して、進みを追う。

```text
取り込みの進み:
- [ ] 0 依頼文に絶対パス、決まり、終わりの条件を入れた
- [ ] 1 報告の主張をひとつずつ差分で裏付けた
- [ ] 1 決まりの表を差分に当てた（落ちたものは差し戻した）
- [ ] 2 マージした（衝突を解いた）
- [ ] 3 マージした結果でチェックを走らせた（落ちたら直して 3 をやり直す）
- [ ] 4 サブエージェントが起こしたものを止め、ワークツリーを片付けた
- [ ] 5 報告を書いた
```

## 0. 依頼する（サブエージェントが始める前に）

- リポジトリ（かそのワークツリー）の絶対パスを渡す。別のフォルダで作業させない。並行作業なら `/itsumo:managing-worktrees` でワークツリーを作って渡す。
- 依頼文に入れるもの: すでに確かめた事実、守るべき決まり（コメントやテスト名の言語、改行、自分のファイルだけをコミット、プッシュしない）、最初に読むページ（アーキテクチャマップがあればそれと、担当範囲の詳細ページ）、終わりの条件（どのチェックが通れば完了か）。
- 報告はユーザーの言語で書かせる。ユーザーには、そのうち大事な部分だけを伝える。

## 1. マージの前に（サブエージェントのブランチを読むだけ）

1. メインのチェックアウトで `git status`。自分の変更を先にコミットして、きれいな状態からマージを始める。`git log main..<branch> --oneline` と `git diff --stat main...<branch>`。
2. **報告と差分を突き合わせる。** 報告の主張（機能、テスト、文書、追加したファイル）ごとに、差分の中に裏付けを探す。裏付けの無い主張や、報告に無い変更は、サブエージェントに差し戻す（SendMessage）か自分で直し、ユーザーへの報告でそう言う。
3. **差分に決まりを当てる**（下の表。プロジェクトに独自の決まりがあればそれも）。落ちたものは差し戻す。通すためにチェックを弱めない。

| 確認 | 方法 |
|---|---|
| 改行 | `node "${CLAUDE_PLUGIN_ROOT}/lib/fix-eol.mjs" --check`。`git diff --stat` に全行が変わったファイルが無い |
| コミットメッセージ | `/itsumo:committing-changes` の形（短い 1 行目、ブランチ名を含まない）。サブエージェント自身のファイルだけ |
| コメントとテスト名 | プロジェクトの決めた言語 |
| テスト | 機能と一緒に足し・直している（`/itsumo:running-regression-tests`）。理由の無い `skip`・`only`・無視指定が無い。1 つのテストファイルに別の領域を混ぜていない |
| 文書 | ユーザーに見える変更・構造の変更・境界の変更に、対応する文書の更新がある |
| 同種の不具合 | 修正なら、同じ種類の不具合を他のどこで探し（他の画面、他の種類、他の言語）、いくつ見つけて直したかを言っている。言っていなければ差し戻す |
| 秘密とデータ | キー、トークン、`.env*`、ユーザーデータ、生成物が差分に無い |
| セキュリティ境界 | 境界を変えていれば `/itsumo:reviewing-security-boundaries` の確認がされている |

## 2. マージ

1. `git merge --no-ff <branch> -m "Merge <何が入ったか>"`（マージコミットのメッセージはブランチ名ではなく中身を言う）。
2. 衝突: 片方が明らかに置き換えたのでなければ、両方を残す。よくあるもの:
   - 両側が末尾にキーを足した JSON（翻訳カタログなど）: 両方残し、古い最終行にカンマを足す。後で `JSON.parse` して確かめる。
   - 一覧や表の文書: 両方の行を残す。
3. 衝突を直すスクリプトは改行を保つように書く（または Edit ツールを使う）。`git diff --stat` で全行が変わったファイルが無いことを確かめる。

## 3. マージの後（ブランチではなく、マージした結果で）

1. マージしたファイルが影響するチェックを走らせる（`/itsumo:running-regression-tests`）。衝突があったら、両側が触った領域のチェックを全部走らせ、その理由を報告に書く。型チェックとリントは毎回。
2. きれいな main でも落ちるものは、その証拠（main で走らせた結果）を付けて既存の失敗として報告する。それ以外の失敗は報告の前に直す。
3. 実環境でしか確かめられない変更（外部サービス、GPU、実機、デスクトップアプリ）は、実環境で確かめるまで「未確認」と報告する。

## 4. 片付け

1. サブエージェントが起こしたまま残したもの（dev サーバー、ポーリングするシェル、起動したプロセス）を止める。ユーザーのアプリやサーバーは決して止めない。
2. ワークツリーは `/itsumo:managing-worktrees` の手順（`worktree.mjs remove`）でだけ消す。リンクを先に外さないと、メインの中身が消えうる。マージされていないブランチは `-D` で消さず、ユーザーに聞く。
3. プッシュは、ユーザーかプロジェクトの指示が main へのプッシュをはっきり許しているときだけ。`--force` は決して使わず、main 以外もプッシュしない。

## 5. 報告

取り込んだブランチ、マージコミットとプッシュしたか否か。差分が裏付けなかったサブエージェントの主張と、差し戻したもの。マージ結果で走らせたコマンドとその結果。既存の失敗とその証拠。確かめていないこと（とその理由）。片付けたもの。
