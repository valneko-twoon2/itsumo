既存のコードに手を入れるときの原則は 1 つ: **差分の全行を、依頼の一文で説明できること**。説明できない行は入れない。

新しいコードを書く場合の流儀の合わせ方は `/itsumo:following-existing-code`、テストの扱いは `/itsumo:running-regression-tests`。

## 1. 変える前に

1. 依頼を 1 文に言い直す（例: 「`calcTax` の端数処理を、切り捨てから四捨五入に変える」）。曖昧なら、直す前に聞く。
2. 変える場所を読む。呼び出し元と、同じ振る舞いに頼る他のコードを探し、**変えない約束**（公開された関数の形、戻り値、ファイル形式、設定名）を確かめる。
3. 直し方が複数あるときは、既存の形に最も近く、触る行が少ないものを選ぶ。

## 2. 変えている間

- **依頼に要る変更だけ**にする。変えた結果、動かなくなる呼び出し元の追従は、依頼に要る変更に含める。
- 次は、依頼に無い限りやらない。近くにあって「良くなる」と思っても同じ。
  - 改名、関数やクラスの分割・統合、ファイルの移動
  - 整形、空白、import の並べ替え、コメントや命名の言い換え
  - 型の厳密化、エラー処理の追加、防御的なチェックの追加（依頼の不具合に関わるものを除く）
  - 依存の追加・更新、設定の整理、使われていないコードの削除
  - 同じ種類の不具合を見つけたときの、依頼の外での修正（見つけたら報告する）
- 既存のコードが好みと違っても、その場所では既存の書き方に合わせる。
- 整形ツールは、変えたファイル全体にかけない。かけるなら、差分の行に限る。

依頼を満たすのに、次の状況になったら**手を止めて聞く**。勝手に進めない。

- 依頼に出てこないファイルや公開された形を変えないと終わらない。
- 直し方が、依頼の想定より大きな書き換えになる。
- 既存の振る舞いを変えてしまう（ほかの利用者が頼っているかもしれない）。

## 3. 終わる前に

進捗のチェックリスト:

```
- [ ] git diff を全部読んだ
- [ ] 各ハンクを、依頼の一文に結び付けられた
- [ ] 空白だけの変更、整形だけの変更、無関係な改名が無い
- [ ] 戻せるものは戻した（依頼と無関係な行）
```

`git diff` を読み、依頼に結び付かないハンクは戻す。戻してから、もう一度 diff を見る。

## 4. 報告

変えたものと、その理由を短く。それに加えて、**触らずに残した気づき**を分けて書く。ユーザーが選べるようにするため。

入力: 「`src/price.ts` の `calcTax` の端数を四捨五入にして」。直す途中で、同じファイルの `formatPrice` に未使用の引数があるのを見つけた。

出力:

```
変えたもの: src/price.ts の calcTax で Math.floor を Math.round に変えた（1 行）。
気づいたが触っていない: formatPrice の第 2 引数が未使用。必要なら別に直す。
```
