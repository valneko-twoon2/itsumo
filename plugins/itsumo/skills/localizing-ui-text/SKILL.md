まずプロジェクトの多言語化の仕組みを調べる: ライブラリ（i18next、react-intl、vue-i18n、gettext、Fluent、Rails I18n など）、カタログの場所（`locales/<lang>/*.json`、`*.po`、`*.ftl`）、どの言語が**主言語**（常に完全）か、文言を足すスクリプト、用語集、カタログを検査するテスト。プロジェクトの決まりが**優先**。決まりが無いところは下の既定に従う。

## 1. 守ること

- **ハードコードしない。** ユーザーが読む文言をコードに直接書かない: 表示する文、`aria-label`、`placeholder`、`title`、通知、エラー表示。翻訳関数（`t('<key>', { name })`）を使い、数で形が変わる文は複数形の仕組み（`<key>.one` / `<key>.other`、ICU の `plural`）を使う。
- **主言語は常に完全、他の言語は後から。** 文言を足すときは、主言語すべてに同じ変更でキーを足す（片方だけ、空のまま、は不可）。他の言語は欠けていてよく、フォールバックの言語で表示される。変更のたびに全言語を手で書かず、作業の区切り・リリース前・ユーザーが求めたときに一括で訳す。
- **主言語の文言を変えたら、他の言語に古い訳を残さない。** 言い換えやプレースホルダの変更も同じ。古い訳を消してフォールバックに戻すか、同時に訳し直す。意図して 1 言語だけ直す（タイポなど）なら、報告に理由を書く。
- **キー**: `<まとまり>.<内容>` の形、小文字、ドット区切り。可変部分は `{name}` で、全言語で同じ名前。文の断片をつなげて文を作らない（語順が言語で違う）。
- **モジュールの読み込み時に翻訳関数を評価しない**（言語の切り替えが効かなくなる）。関数か getter にする。
- **訳さないもの**: 製品名・モデル名などの固有名、列挙値、`data-testid`、ショートカットキー。モックやテストは対象外。
- **用語をそろえる。** 同じ概念には同じ言葉を使い、まず既存の訳を探す（`grep -rn "<語>" <カタログの場所>/<lang>`）。用語集（無ければ作ってよい: 概念ごとに各言語の正しい語、避ける語、理由）があれば書く前に読む。
- **文書が文言を参照していれば直す。** キーを消す・名前を変える・プレースホルダを足すと、それを引用するマニュアルやテストが壊れる（`/itsumo:syncing-docs`）。
- **言語を足す・消すときは、全部を 1 コミットで揃える**: すべてのまとまりのカタログ、言語の一覧、設定画面の選択肢（言語の名前はその言語自身の表記: `Français`）、E2E テストの言語一覧、文書のフォルダ。中途半端な言語を残さない。

## 2. 手順

### 文言を足す・変える

1. 既存のキーと、同じ用語の既存の訳を探す。
2. 主言語すべてに、同じプレースホルダでキーを足す（プロジェクトに追加スクリプトがあればそれで）。
3. コードでキーを使う。
4. キーを変えた・消したなら、それを引用する文書とテストを直す。

### 足りない訳を追いつかせる

1. 主言語にあって他の言語に無いキーを一覧する（スクリプトがあればそれで。無ければカタログを比べる）。
2. 言語ごとにまとめて訳す。補助のサブエージェントに 1 言語ずつ任せてよい（依頼文: その言語のカタログの用語に合わせる、同じ `{placeholders}`、主言語には触らない）。
3. カタログの検査（キーの一致、プレースホルダの一致）を走らせる。

### 言語を足す

上の「全部を 1 コミットで」の一覧どおり。日付や数は `Intl`（やライブラリの書式機能）で今の言語を使っていれば普通は何も要らないが、日付の絞り込みや長い言語（ドイツ語など）での文字のはみ出しは目で確かめる。

## 3. 確認

カタログの検査テスト（主言語のキーの一致、他の言語に主言語に無いキーが無い、プレースホルダの一致、ハードコードの検出）、型チェック（キーに型がある場合）、文言の長さで崩れないかの画面の確認。プロジェクトに無ければ、少なくとも主言語のキー集合の一致を確かめる。

## 4. 報告

主言語に何を足したか、他の言語にいくつ訳が足りないか（または埋めたか）、文書を直したか（直していないならその理由）。
