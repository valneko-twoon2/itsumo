# ひな形と形式

## 目次

1. AGENTS.md
2. rules
3. skills
4. .claude/itsumo.json

## 1. AGENTS.md

**短く**（目安は 100 行以内）。コードを読めば分かること、一般論、README の写しは書かない。書くのは、Claude が間違えやすいこと、コードから読み取れない決まり。

```markdown
# AGENTS.md

<プロジェクトが何か。1〜2 文>

## 構成

| 場所 | 中身 |
|---|---|
| `src/...` | ... |

## コマンド

\`\`\`sh
<導入>
<ビルド>
<テスト（全体）>
<テスト（1 ファイル）>
<リント・型チェック>
\`\`\`

## 決まり

- <コードから読み取れない決まり。例: 「API の入力は zod で検証する」>
- <やってはいけないこと。例: 「生成物の `src/gen/` を手で直さない」>

## 注意

- <壊れやすい場所、環境に依存する点>
```

- コマンドは、実際に走らせて確かめたものだけを書く。
- 「決まり」は、複数のファイルで実際に守られていると確かめたものだけ。推測を決まりにしない。
- 既にある文書（README、CONTRIBUTING）にあることは、書き写さず、場所を示す。

## 2. rules

`.claude/rules/<名前>.md`。特定の場所にだけ効く決まり。

```markdown
---
paths:
  - "src/api/**/*.ts"
---

- <この場所のファイルを触るときだけ要る決まり>
```

- `paths` で指定した場所のファイルを触るときだけ読み込まれる。全体に効く決まりは AGENTS.md に書く。
- 決まりは、そのまま守れる形で書く（「適切に」でなく、具体的に）。

## 3. skills

`.claude/skills/<名前>/SKILL.md`。プロジェクトで繰り返す手順。

```markdown
---
name: <動名詞形、小文字・数字・ハイフン。例: adding-api-endpoint>
description: "<何をするか。いつ使うか（ユーザーの言い回しを含める）。三人称>"
---

<手順。触るファイル、順番、確かめ方。プロジェクト固有のことだけ>
```

- 手順が決まっているものだけをスキルにする。1 回限りの作業や、判断が毎回違うものはしない。
- 本文は簡潔に。Claude が知っている一般論は書かない。
- 触るファイルの組み合わせは、`git log --stat` で実際に一緒に変わっていたものにする。

## 4. .claude/itsumo.json

itsumo プラグインの設定。調べて分かったことだけを書く。

```json
{
  "worktree": { "link": ["node_modules"] },
  "stop": { "ignore": ["dist/", "coverage/"] }
}
```
