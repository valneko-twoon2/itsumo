取り返しのつかない操作は、**対象を見て、戻し方を用意して、了承を得てから**実行する。速さより確実さを取る。

itsumo のフックは、再帰的な削除、強制 push、`reset --hard`、`clean -f`、ブランチの強制削除、変更の破棄、テーブルの `DROP` などを、実行前にユーザーへ確認させる。フックが拾わない操作（クラウドの CLI、本番の API、一括の `UPDATE`、公開）も、このスキルの対象。

## 1. 手順

進捗のチェックリスト:

```
- [ ] 1. 対象を一覧で見た（消すファイル、書き換わるコミット、変わる行数）
- [ ] 2. もっと弱い操作で足りないか考えた
- [ ] 3. 戻し方を用意した
- [ ] 4. 対象・影響・戻し方を示して、ユーザーの了承を得た
- [ ] 5. 実行し、結果を確かめた
```

### 1. 対象を見る

実行する前に、同じ条件で**読むだけ**の操作をして、対象を確かめる。

| 操作 | 先に見るもの |
|---|---|
| ファイルの削除 | `ls` や `git status --ignored` で対象を一覧する。ワイルドカードは展開した結果を見る |
| `git clean` | `git clean -n`（消えるものの一覧） |
| `git reset --hard`、変更の破棄 | `git status` と `git diff`。捨てる変更に、自分のものでない変更が無いか |
| 強制 push | `git log origin/<branch>..HEAD` と `git log HEAD..origin/<branch>`（消えるリモートのコミット） |
| ブランチの削除 | `git branch --merged`、そのブランチの未マージのコミット |
| DB の書き換え | 同じ条件の `SELECT count(*)`。マイグレーションは中身と、戻す手順（down）を読む |

対象が想定より多い・違うなら、止めてユーザーに伝える。

### 2. 弱い操作で足りないか

| したいこと | 先に考える、弱い操作 |
|---|---|
| `git push --force` | `git push --force-with-lease`（他人の push を消さない） |
| `git reset --hard` | `git stash`、または新しいブランチに退避してから |
| `rm -rf` | 移動（ゴミ箱、退避フォルダ）。消すのは確かめた後 |
| `git branch -D` | `git branch -d`（マージ済みのものだけ消える） |
| 一括の `DELETE` / `UPDATE` | 範囲を絞る。トランザクションの中で、件数を見てからコミット |

### 3. 戻し方を用意する

- Git: 今の位置にタグかブランチを付ける（`git branch backup/<日付>-<名前>`）。`git reflog` で戻れることも確かめる。
- ファイル: 退避先へコピーするか、Git に入っていることを確かめる。
- DB: バックアップ、または down のマイグレーション。本番は、バックアップが無ければ実行しない。

### 4. 了承を得る

次を短く示して、ユーザーに聞く（`AskUserQuestion` があれば使う）。了承が無ければ実行しない。

```
操作: 何を実行するか（コマンド）
対象: 何が消える・変わるか（件数、一覧の要点）
戻し方: どうすれば元に戻せるか
```

**一度の了承は、その操作だけに有効。** 似た操作を後でするときも、改めて聞く。ユーザーが最初から明示的に頼んだ操作でも、対象が想定より大きければ聞き直す。

### 5. 実行して確かめる

- 実行した後、結果を確かめる（`git status`、`git log`、件数）。
- 想定と違ったら、それ以上操作を重ねず、すぐに報告する。用意した戻し方を示す。

## 2. しないこと

- 自分が作ったのではないファイル、変更、ブランチ、プロセスを、確かめずに消さない。
- 確認を避けるために、操作を別の形（別のコマンド、スクリプトの中）に言い換えない。
- フックやツールの確認を、設定を変えて外さない。
