コミットメッセージは、`git log` を読む人がそのコミットを見つけられるように「何のコミットか」を言う。細部は差分・テスト・文書にあるので、メッセージには書かない。

## 1. コミットの前に

1. `git status` で変更を見る。**自分の変更だけ**を名前を指定してステージする（`git add -A` や `git add .` は使わない）。ユーザーや他のエージェントの変更が混ざっていたら触らない。
2. `git diff --cached` でステージした中身を読む。
3. 次のものは決してコミットしない: `.env*`、API キーやトークン、秘密鍵、ユーザーデータ、生成物（ビルド出力、カバレッジ、テスト結果）、作業用の一時ファイル。見つけたらステージから外して報告する。
4. 変更に合ったチェックを走らせる（`/itsumo:running-regression-tests`）。落ちたまま黙ってコミットしない。
5. リポジトリに改行の指定（`.gitattributes`）があれば、`node "${CLAUDE_PLUGIN_ROOT}/lib/fix-eol.mjs" --check` で確かめる。
6. リポジトリにコミット規約（`CONTRIBUTING.md`、commitlint、Conventional Commits、既存の `git log` の流儀）があれば、**そちらを優先**する。下の形はそれが無いときの既定。

## 2. 形

| 部分 | 決まり |
|---|---|
| 1 行目 | コミット全体の要点を 1 行で。72 文字以内、句点で終えない。動詞（英語なら "Add"、"Fix"、"Remove"）か、それに当たる言い方で始める。リポジトリの履歴が Conventional Commits（`feat:`、`fix:`、`chore:`、`docs:`、`refactor:`、`test:`）ならその接頭辞で始める。何を変えたかと、短ければ何のためか。無関係な変更を並べない。並べたくなるなら 2 コミットに分ける |
| 本文 | 1 行目で足りないときだけ。空行を挟み、最大 8 行。各行は `- ` で始まる 1 行の箇条書き（100 文字以内、折り返さない） |
| トレーラー | プロジェクトが求めるものだけ。**Claude の署名行（`Co-Authored-By: Claude ...`）は付けない**（フックが止める。`attribution: true` の設定があるプロジェクトを除く）。空行の後に置き、上の制限には数えない |

小さい・明らかな変更（タイポ、名前の変更、1 つの修正）は **1 行目だけ**。

メッセージの言語はリポジトリの既存のコミットに合わせる。

## 3. 箇条書きに入れるもの

- 読む人が探しそうな粒度の、主なこと: 足した機能、変わった振る舞い、消したもの、差分からは分からない判断とその理由。
- 入れないもの: ファイル一覧、関数名の羅列、作業の経緯、テストのコマンドと結果（それは報告に書く）、「ついでに直した」小物の一覧、1 行目の言い直し。
- 入れないもの: ブランチ名やタグ名（`worktree-agent-...`、`claude/...`、今いるブランチ）。どこで作ったかはログにある。
- 8 行を超えそうなら、大事な 8 行を残して残りは 1 行目に任せるか、コミットを分ける。

## 4. 例

入力: ページ一覧をサムネイルの帯で見せるようにした。最大 10 ページを幅に合わせて出し、前後に送る矢印も付けた
出力:
```text
feat: ページをサムネイルの帯で表示する

- 帯は幅に合わせて最大 10 ページを出し、前後のグループへ送る矢印を付ける
- ゴミ箱ボタン 1 つで選択中の項目を消す。Delete キーでも同じ
```

入力: 日付がタイムゾーン変換でずれる不具合を直した
出力:
```text
fix: タイムゾーン変換で日付が 1 日ずれるのを直す
```

入力: 依存パッケージを最新にした
出力:
```text
chore: 依存パッケージを更新する
```

## 5. その後

- プッシュはしない。ユーザーかプロジェクトの指示がはっきり許しているときだけ。`--force` は決して使わない。
- フック（pre-commit、commit-msg）に落とされたら、原因を直して新しくコミットし直す。`--no-verify` で飛ばさない。
- 報告には、コミットのハッシュと 1 行目、走らせたチェックとその結果、コミットしなかったもの（とその理由）を書く。
