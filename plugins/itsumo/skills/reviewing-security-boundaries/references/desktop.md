# デスクトップアプリ、WebView アプリ、CLI の確認表

共通の確認（SKILL.md の 3 章）に加えて、変える境界に当たる行を確かめる。

| 境界 | 確かめること |
|---|---|
| コマンドの入口 | 画面（WebView）から呼べるコマンドや IPC は、新しいものを許可リストや権限設定に**明示的に**足す。必要以上の権限（ファイルシステム全体、任意のシェル、任意の HTTP）を与えるプラグインや設定を足さない。引数は呼ぶ側の UI を信用せず、コマンドの中で検証する |
| WebView、HTML | CSP を緩めない（`'unsafe-eval'`、外部の `script-src`、`*`、`connect-src` への外部ホスト）。データはフレームワークで描画し、HTML 文字列を DOM に入れない（`innerHTML`、`dangerouslySetInnerHTML`、`v-html`）。`eval`、`new Function`、文字列の `setTimeout`、`javascript:` URL を使わない。外部サイトを読み込む画面に、アプリのコマンドを許さない |
| 画面から OS への経路 | Electron は `nodeIntegration` を切り、`contextIsolation` を入れ、preload で出す関数を最小にする。外部の URL を開くときは `https` と許可したホストだけに絞る |
| プログラムの起動 | 共通の表に加えて、アプリが同梱する実行ファイルは絶対パスで起動し、`PATH` 任せにしない。作業フォルダを信用できないフォルダにしない |
| 秘密の保存 | OS の保護された保存先（Windows の DPAPI と資格情報マネージャ、macOS の Keychain、Linux の libsecret）を使う。設定ファイルや平文の JSON に置かない。ログや診断情報、クラッシュレポートにも出さない |
| アップデート | 配信物には署名を付け、アプリ側で検証してから入れる。更新の取得は `https` だけにする |
| ローカルのサーバー | アプリが待ち受けるポートは `127.0.0.1` に限る。他のプロセスや Web ページから叩かれても困らないよう、トークンかオリジンの確認を付ける |
| テスト用の抜け穴 | テストのための環境変数やフラグはデバッグビルドでだけ読み、リリースでは無視する。持たせるのは時間や回数だけにし、パス・URL（ループバック以外）・プログラム名・秘密・何を読み書き実行送信するかを決める値は決して取らない。抜け穴を足したら、パーサの単体テストと、変数が無いとき本物の値が使われるテストを足す |
| ユーザーが開くファイル | 開いたファイルの中身は外部データとして扱う（共通の表）。ダブルクリックで開く形式を足すなら、壊れたファイルや巨大なファイルで落ちないことを確かめる |
| CLI | 引数や環境変数をシェルに渡さない。パスは正規化して、決めた範囲の外を触らない。`--force` のような破壊的な操作は、既定で確認を挟む |
